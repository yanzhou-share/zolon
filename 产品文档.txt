1. 项目背景与目标
产品背景：智能收银终端 - AI 销售助手系统。针对餐饮与零售场景，传统人工销售响应慢、话术不统一。

核心目标：构建一套基于 LangGraph 的 AI Agent 系统，实现 24/7 自动化销售咨询与初步转化。

预期效果：降低人工接待成本，提升咨询转化率至 15% 以上，实现情绪闭环风控。

2. 系统功能模块 (LangGraph 节点设计)
系统采用图状态机 (Graph State) 架构，由以下核心节点组成：

节点 1：Input_Collector (输入汇总)
功能：对实时消息进行 5 秒窗口期缓冲。
动作：将多条碎片化消息合并为一条完整的"用户请求"。

节点 2：Sentiment_Analyzer (情绪分析器)
功能：实时判定用户情感等级（使用 DeepSeek LLM）。
逻辑：检测到"辱骂/愤怒"关键词或语气，标记为 Handover 状态。

节点 3：Query_Optimizer (意图优化器)
功能：解析用户真实意图，提取产品关键词（使用 DeepSeek LLM）。

节点 4：Knowledge_Retriever (RAG 知识库)
功能：基于 ChromaDB 进行语义搜索，从上传的知识库中检索相关信息。

节点 5：Response_Generator (销售回复生成器)
功能：结合检索到的知识，生成具备同理心且专业的回复（使用 DeepSeek LLM）。

节点 6：Human_Handover_Router (转人工调度器)
功能：根据节点 2 的标记，决定是发送 AI 回复，还是触发转人工指令。

3. 业务流程逻辑 (Workflow)
开始 -> 输入汇总。

情绪分析：

若判定为 愤怒 (Angry)：跳转至 转人工节点，结束会话流。

若判定为 正常 (Normal)：继续执行。

知识匹配：调用 RAG 节点从上传知识库中检索相关信息。

回复生成：基于检索到的知识，使用 LLM 生成专业回复。

结束 -> 输出响应。

4. 核心功能

4.1 知识库管理
- 支持上传 .txt 和 .docx 文件
- 文件内容自动切分（500字/片段，50字重叠）
- ChromaDB 持久化存储，重启后保留
- 支持查看和删除已上传文件

4.2 LLM 集成
- DeepSeek LLM 用于情绪分析、意图优化、回复生成
- 无 API Key 时降级到关键词匹配
- SSE 流式响应，逐 token 输出

4.3 Embedding 模型
- BGE-small-zh 用于向量检索（后台异步加载，不阻塞启动）
- 模型缓存到本地，避免重复下载

5. 非功能需求
响应时效：全链路处理延迟 < 5 秒。

系统稳定性：引入异构合并策略，防止连续消息触发重复逻辑。

可观测性：每一轮对话需记录 Input, Sentiment_Score, Retrieved_Knowledge, Final_Output 以便后期 AI 调优。

会话持久化：对话历史保存到本地 JSON 文件，刷新页面不丢失。

6. 销售话术 SOP (Agent 注入背景)
Agent 将被注入以下核心背景知识：

语气设定：专业、热情、高效。

回复规则：优先使用检索到的知识回答，如无相关信息则告知客户。
